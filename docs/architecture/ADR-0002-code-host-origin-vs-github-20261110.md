# ADR-0002: Cursor Origin vs GitHub as code host

## Status

**Proposed** — 10 November 2026 AEDT. ADR-0001 already exists; 0002 was the next unused number **only in `/workspace/thunderstone/drafts/`**. ModMe `docs/adr/` and `next-forge/docs/adr/` are separate inventories, not renumbered by this bundle. This is not approval to migrate, create a repository, mirror, install apps or spend money. ADR form follows [Nygard](https://www.cognitect.com/blog/2011/11/15/documenting-architecture-decisions); rationale follows [ADR guidance](https://adr.github.io/).

## Context

Need low-cost code hosting that works with Cursor CLI/cloud agents, CI, CodeRabbit and cubic, while enforcing checks/reviews. Existing work in the supplied brief uses GitHub PRs. Origin is documented as early beta; do not infer GitHub parity from “git forge”. [Origin overview](https://cursor.com/docs/origin.md).

All product facts below were fetched on 10 November 2026 AEDT, not tested against the user's tenant. Public list prices are not an account quote or total-cost estimate. No plan, key, live protection settings or installed-app settings were inspected. SWE application additionally inspected local repo files and read first-party repository metadata: **both repos are public, user-owned, default branch `main`**. [ModMe metadata](/workspace/thunderstone/artifacts/arch-framework-swe-sources-20261110/modme-ui-01-metadata-mcp.txt); [Starter metadata](/workspace/thunderstone/artifacts/arch-framework-swe-sources-20261110/thunderstone-starter-metadata-mcp.txt).

## Proposed decision

Retain **GitHub as forge of record for this system for now**, primarily because hosted cubic support is explicitly GitHub-only and the supplied project flow already depends on GitHub PR/CI gates. Treat Origin as an option to revisit, not an inferior/non-functional host. It now documents CI apps, CodeRabbit and merge protections; do not claim those are absent. [Hosted support](https://docs.cubic.dev/); [Origin integrations](https://cursor.com/docs/origin/apps.md); [Protection UI](https://cursor.com/docs/origin/settings.md).

No Origin pilot or mirror is created by this decision. A later approved pilot can compare one representative contract/module-test workflow, review bots and enforced merge gates before a new decision. This experiment is a local proposal informed by both hosts' documented integrations. [Origin CI](https://cursor.com/docs/origin/clonekit-ci.md); [Actions](https://docs.github.com/en/actions/get-started/understand-github-actions).

### Current plan/owner applicability

Both targets are public and personally owned, so the generic private-repo paid-protection caveat is **not currently binding**. GitHub documents “restrict who can push” for organisation-owned repositories; do not promise it on these user-owned repos. Verify available controls in the actual tenant before acceptance; no Settings changed. [Visibility and organisation-only controls](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches); [Local snapshot inventory](/workspace/thunderstone/artifacts/arch-framework-swe-sources-20261110/repositories.json); [Host metadata](/workspace/thunderstone/artifacts/arch-framework-swe-sources-20261110/modme-ui-01-metadata-mcp.txt).

## Consequences and trade-offs

- Preserves the documented GitHub hosted-review path; would require rechecking paid-plan eligibility if visibility changed to private (not the current case), plus existing Cursor/runner/review-bot charges. No cost saving is asserted. [Private-repo plan limits](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches); [Plans](https://github.com/pricing); [Cursor usage](https://cursor.com/docs/models-and-pricing.md).
- Defers potential Origin workflow consolidation and beta evaluation. Git portability does not by itself migrate review state, checks or app installations; mirrored PRs and integrations stay on GitHub. [Beta/forge model](https://cursor.com/docs/origin.md); [Mirrored PRs](https://cursor.com/docs/origin/pull-requests.md); [Mirror integration behaviour](https://cursor.com/docs/origin/apps.md).
- Proposed safeguards on either host: no force-push/history rewrite, review dismissal or protection bypass; **never directly push `main`**. Commit, push, merge, deploy, migration and deletion need **DT's own exact approval words**; approved git operations go through **Git-Scout**. Drive authoring ownership is unchanged. This document authorises no live write. These are project constraints, not claims about product defaults. [Product controls](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches); [Review/merge mechanics](https://cursor.com/docs/origin/pull-requests.md).
