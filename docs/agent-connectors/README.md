# Agent connectors for Grok, Grok Bot and Cursor

This folder configures MCP connectors, browser tooling and skills for three surfaces:

| Surface | Reads | Generated by |
|---|---|---|
| Grok Build CLI and Grok Bot (shared VM) | `.grok/config.toml`, `.agents/skills/` | `scripts/mcp-sync.mjs`, `scripts/skills-install.sh` |
| Cursor (desktop and cloud agents) | `.cursor/mcp.json`, `.agents/skills/` | the same scripts |
| Perplexity Computer and Comet | nothing in this repo | not configured here; guides live in Drive `00_INBOX/Thunderstone/` |

Do not confuse the two groups: nothing in this repo changes Perplexity Computer or Comet. Their connectors and skills are added through the Perplexity web or desktop app.

## What starts automatically

`scripts/agent-setup.sh` is the single idempotent entry point. Every step is best effort and never starts a paid agent task.

| Hook | Calls | Does |
|---|---|---|
| `scripts/bootstrap.sh` (Cursor `install`, first VM setup) | `agent-setup.sh --install` | installs agent-browser, pulls the CloakBrowser image, installs skills, installs Cua Driver on the VM profile, renders MCP configs |
| `scripts/resume.sh` (Cursor `start`, VM desktop login) | `agent-setup.sh --start` | starts the CloakBrowser sidecar if Docker is up, re-renders MCP configs |
| `scripts/doctor.sh` | `agent-setup.sh --doctor` | reports what is ready |

Run any mode by hand: `bash scripts/agent-setup.sh --install|--start|--sync|--doctor`.

## Servers

Source of truth: `config/mcp/servers.json`. A server is written only when its profile matches, its required env vars are set, and its binaries exist, so a half-configured machine never gets broken entries. The sync output lists every skip and why.

| Server | Profiles | Default | Needs |
|---|---|---|---|
| `perplexity` (search, ask, research, reason) | dev, vm | on | `PERPLEXITY_API_KEY` |
| `context7` | dev, vm | on | optional `CONTEXT7_API_KEY` |
| `firecrawl` | dev, vm | on | `FIRECRAWL_API_KEY` |
| `browser` (agent-browser on CloakBrowser CDP) | dev, vm | on | `agent-browser` on PATH |
| `scrapling` | dev, vm | on | `scrapling` on PATH |
| `chrome-devtools` | dev, vm | off | enable with `MCP_ENABLE=chrome-devtools` |
| `computer-use` (`computer-use-mcp`, nut.js) | vm | on | X11 display |
| `cua-driver` (trycua) | vm | on | installed by `--install` |
| `perplexity-computer` (delegate tasks, OAuth) | dev, vm | off | enable with `MCP_ENABLE=perplexity-computer` |

Profiles: `vm` is the Grok Bot VM and `dev` is everything else. The profile comes from `THUNDERSTONE_PROFILE`, or defaults to `vm` on an Xfce desktop. `scripts/install-desktop.sh` writes `THUNDERSTONE_PROFILE=vm` to `~/.config/thunderstone/env` once.

Toggles: `MCP_ENABLE=id,id` and `MCP_DISABLE=id,id`. Each enabled server adds tool definitions to every request, so leave rarely used ones off.

## The VM belongs to the Grok Bots

The Grok Bot VM is a lightweight Xfce desktop that the bots own and fully control. Computer-use tooling there (`computer-use`, `cua-driver`) is intentionally unrestricted, and Cua Driver runs in its default `standard` mode that allows input to every app. On any other machine the `dev` profile leaves both off, because there they would drive a person's real desktop.

## Secrets

Keys never go in the repo or generated files. Put them in `~/.config/thunderstone/env` (preferred, works from any working directory) or `.env.local`. The generated configs launch each server through `scripts/env-run.mjs`, which injects the keys at start. See `.env.example` for names.

## Files you may edit by hand

`mcp-sync` refuses to overwrite a `.grok/config.toml` or `.cursor/mcp.json` it did not generate (override with `node scripts/env-run.mjs node scripts/mcp-sync.mjs --force`). Grok Build also reads `.cursor/mcp.json`, so a server with the same name in both files is defined once.
